# 사전 배포 워크시트: JOIN 감각 되살리기

> 7주차 Day 2 수업 전 자기주도 복습용 워크시트. 소요 30-40분. 정답은 맨 뒤에 있습니다.

---

## 0. 왜 이 워크시트인가

내일(Day 2)은 이번 주에서 코드량이 가장 많은 날입니다. 2,400만 행짜리 거래 테이블에 사용자와 카드 테이블을 이어 붙이는 3-way JOIN이 수업 내내 등장합니다. 큰 데이터 위에서 JOIN 개념까지 동시에 떠올리려면 머리가 두 배로 바쁩니다. 그래서 오늘은 **눈으로 전부 셀 수 있는 5행짜리 장난감 테이블**로 JOIN 근육만 미리 풀어 둡니다.

여기서 훈련할 감각은 딱 세 가지입니다.

- (1) 조인 결과의 **행 수를 실행 전에 예측**하기
- (2) LEFT JOIN에서 **NULL이 어느 컬럼에 생기는지** 예측하기
- (3) 1:N 관계에서 **행이 불어나는(fan-out)** 순간 알아채기

이 세 감각만 있으면 내일 어떤 쿼리를 만나도 "결과가 대충 몇 행쯤, 어떤 모양으로 나오겠구나"를 그릴 수 있습니다.

## 1. 준비: 설치도 적재도 필요 없습니다

BigQuery 콘솔([console.cloud.google.com](https://console.cloud.google.com) → BigQuery Studio)의 쿼리 편집기만 열면 됩니다. 아래 장난감 테이블은 WITH 절로 쿼리 안에서 직접 만들기 때문에 테이블 적재가 필요 없고, 실제 테이블을 읽지 않으므로 **처리 바이트도 0 B**입니다 (마음껏 실행하세요).

아래 블록이 오늘의 공용 재료입니다. 모든 문제에서 이 블록을 복사한 뒤, 마지막 SELECT만 바꿔 가며 풀면 됩니다.

```sql
-- 공용 재료: 이 WITH 블록을 복사해서 쓰세요
WITH mini_users AS (
    -- 고객 5명
    SELECT 1 AS user_id, '지민' AS name, 'F' AS gender, 24 AS age UNION ALL
    SELECT 2, '서준', 'M', 31 UNION ALL
    SELECT 3, '하은', 'F', 27 UNION ALL
    SELECT 4, '도윤', 'M', 45 UNION ALL
    SELECT 5, '유나', 'F', 52
),
mini_tx AS (
    -- 거래 7건 (user_id 7번은 고객 테이블에 없는 유령 거래)
    SELECT 101 AS tx_id, 1 AS user_id, '외식' AS category, 12.5 AS amount UNION ALL
    SELECT 102, 1, '식료품', 54.3 UNION ALL
    SELECT 103, 2, '주유', 40.0 UNION ALL
    SELECT 104, 3, '외식', 8.9 UNION ALL
    SELECT 105, 3, '외식', 15.0 UNION ALL
    SELECT 106, 3, '식료품', 62.1 UNION ALL
    SELECT 107, 7, '외식', 9.9
)

SELECT * FROM mini_users;    -- 이 줄을 문제마다 바꿔 가며 풉니다
```

표로 보면 다음과 같습니다. 문제를 풀 때 이 표를 손가락으로 짚으며 세어 보세요.

**mini_users (고객 5명)**

| user_id | name | gender | age |
| --- | --- | --- | --- |
| 1 | 지민 | F | 24 |
| 2 | 서준 | M | 31 |
| 3 | 하은 | F | 27 |
| 4 | 도윤 | M | 45 |
| 5 | 유나 | F | 52 |

**mini_tx (거래 7건)**

| tx_id | user_id | category | amount |
| --- | --- | --- | --- |
| 101 | 1 | 외식 | 12.5 |
| 102 | 1 | 식료품 | 54.3 |
| 103 | 2 | 주유 | 40.0 |
| 104 | 3 | 외식 | 8.9 |
| 105 | 3 | 외식 | 15.0 |
| 106 | 3 | 식료품 | 62.1 |
| 107 | 7 | 외식 | 9.9 |

일부러 심어 둔 어긋남 두 가지를 미리 봐 두세요.

- (1) 도윤(4)과 유나(5)는 **거래가 한 건도 없습니다**
- (2) 거래 107은 user_id가 7인데, **고객 테이블에 7번이 없습니다** (전산 오류로 생긴 유령 거래라고 합시다)

## 2. 1분 요약: 딱 세 줄만 기억하세요

- (1) INNER JOIN은 **짝이 있는 행만** 남깁니다. 짝 없는 행은 조용히 사라집니다.
- (2) LEFT JOIN은 **왼쪽 테이블의 행을 전부** 지킵니다. 짝이 없으면 오른쪽 테이블에서 온 컬럼이 NULL로 채워집니다.
- (3) 왼쪽 한 행에 오른쪽 짝이 N개면 결과는 **N행으로 불어납니다** (1:N fan-out).

## 4. 정답과 해설

### Q1 정답

- 행 수: **6행** (tx 101부터 106까지)
- 등장하지 않는 고객: **도윤, 유나** (거래가 없어 짝이 없음)
- 등장하지 않는 tx_id: **107** (user_id 7이 고객 테이블에 없음)
- 해설: INNER JOIN은 양쪽 모두 짝이 있어야 살아남습니다. 거래 없는 고객 2명과 유령 거래 1건이 **아무 경고 없이 조용히 사라진다**는 점이 핵심입니다. 실무 사고의 대부분은 이 "조용히"에서 시작됩니다.

### Q2 정답

- 행 수: **8행** = 지민 2 + 서준 1 + 하은 3 + 도윤 1 + 유나 1
- 해설: LEFT JOIN은 왼쪽(고객) 5명을 전원 지킵니다. 짝이 여러 개면 그만큼 불어나고(지민 2행, 하은 3행), 짝이 없어도 1행은 남습니다(도윤, 유나). "왼쪽 행 수 그대로"가 아니라 "왼쪽 행마다 max(짝 수, 1)행"임에 주의하세요. 유령 거래 107은 오른쪽에만 있으므로 여기서는 등장하지 않습니다.

### Q3 정답

- NULL이 있는 행: **2개** (도윤 행과 유나 행)
- NULL이 생기는 컬럼: **tx_id, category, amount** (오른쪽 mini_tx에서 온 컬럼 전부)
- 해설: LEFT JOIN에서 NULL은 항상 **오른쪽** 테이블에서 온 컬럼에 생깁니다. 왼쪽 행은 원본 그대로 지켜지고, 짝을 못 찾은 자리(오른쪽 컬럼)만 비기 때문입니다.

### Q4 정답

- 행 수: **7행** (거래 7건 전원 생존)
- NULL 행: **tx_id 107**, NULL 컬럼은 **name과 gender**
- 해설: 왼쪽이 거래로 바뀌었으므로 이번엔 거래가 전원 생존하고, 고객 정보를 못 찾은 유령 거래 107의 고객측 컬럼이 빕니다. **LEFT JOIN에서 "누가 전원 생존하는가"는 오직 어느 테이블을 왼쪽에 놓았는가로 결정됩니다.** 같은 재료라도 질문("모든 고객 기준인가, 모든 거래 기준인가")에 따라 방향을 골라야 합니다.

### Q5 정답

- (가): **LEFT**  (나): **ON**  (다): **IS NULL**
- 결과: **도윤**과 **유나**
- 해설: "없는 것"은 INNER JOIN으로 찾을 수 없습니다(없는 행은 결과에 아예 안 나오니까요). LEFT JOIN으로 전원을 살려 둔 뒤, 짝이 없어 NULL이 된 행만 WHERE로 골라내는 이 패턴을 **안티 조인**이라고 부릅니다. NULL 비교는 `= NULL`이 아니라 반드시 `IS NULL`을 써야 한다는 것도 다시 확인하세요.

### Q6 정답

- 27은 **3번** 등장 (하은의 거래가 3건이라 하은의 행이 3행으로 복제됨)
- SUM(u.age)는 179가 **아닙니다**. 지민 24가 2번, 하은 27이 3번 더해져 24x2 + 31 + 27x3 + 45 + 52 = 257이 나옵니다.
- 해설: 조인은 값을 "복제"합니다. 1:N 조인 후에 1쪽 컬럼을 SUM이나 AVG 하면 N만큼 중복 합산됩니다. **조인 후 합계가 이상하게 크면 fan-out부터 의심하세요.** 내일 3-way JOIN에서 이 함정이 실전 크기로 등장합니다.

### Q7 정답

- (가): **t.tx_id**  (나): **u.name** (또는 u.user_id, u.name — 이름이 겹칠 수 있는 실전에서는 user_id로 묶는 편이 안전합니다)
- 도윤의 n_tx: **0**
- COUNT(*)를 쓰면: **1** (도윤의 행 자체는 1개 존재하므로)
- 해설: COUNT(*)는 행을 세고, COUNT(컬럼)은 그 컬럼이 NULL이 아닌 행만 셉니다. "0건 포함 집계"는 LEFT JOIN과 COUNT(오른쪽 컬럼)의 합작으로만 만들어집니다.

### Q8 정답

- (a) 행 수: **6행**, SUM(t.amount) = **130.0**
  - 지민(user 1)의 카드가 2장이라, 지민의 거래 201과 202가 각각 카드 2장과 매칭되어 2행씩으로 불어납니다. 10.0과 20.0이 두 번씩 합산되어 130.0이 됩니다.
- (b) 빈칸: **AND t.card_id = c.card_index**
- 해설: 복합 키 테이블은 **키의 모든 조각을 ON 절에 걸어야** 행 하나가 정확히 하나와 만납니다. 조각 하나를 빠뜨린 조인은 에러 없이 실행되고 그럴듯한 결과를 내놓기 때문에 가장 위험합니다. 내일 cards 테이블 조인에서 이 조건이 그대로 등장합니다.

## 5. 내일과의 연결

오늘 5행짜리 표에서 한 일이 내일은 이렇게 커집니다.

| 오늘 (장난감) | 내일 (실전) |
| --- | --- |
| mini_users 5행 | users 약 2,000행 |
| mini_tx 7행 | transactions 약 2,400만 행 |
| mini_cards의 (user_id, card_index) | cards의 (user, card_index) 복합 키 |
| Q5 거래 없는 고객 찾기 | "한 번도 거래하지 않은 카드를 가진 사용자는 몇 명인가?" |
| Q8 fan-out 함정 | 3-way JOIN에서 금액이 부풀려지는 실전 함정 |

표가 커져도 규칙은 하나도 변하지 않습니다. 내일 쿼리가 복잡해 보이면, 머릿속에서 테이블을 5행으로 줄여서 생각하세요.
