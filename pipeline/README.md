# DART → BigQuery 주간 배치

OpenDART 재무제표를 매주 월요일 오전 8시(KST)에 BigQuery `dart.fs_long`으로 적재합니다.
GitHub Actions에서 돌기 때문에 PC를 켜 둘 필요가 없고, 퍼블릭 레포라 비용이 들지 않습니다.

## 처음 한 번만 해야 하는 준비

### 1. DART API 키 재발급

기존 키는 노트북 파일에 평문으로 남아 노출된 상태입니다.
[OpenDART 마이페이지](https://opendart.fss.or.kr/mng/apiKeyMng.do)에서 재발급받으세요.

### 2. GCP 서비스 계정 만들기

배치는 사람 계정이 아니라 서비스 계정으로 BigQuery에 붙습니다.

1. GCP 콘솔 → IAM 및 관리자 → 서비스 계정 → **서비스 계정 만들기** (이름 예: `dart-batch`)
2. 역할 두 개를 부여합니다.
   - **BigQuery 데이터 편집자** (테이블 생성·덮어쓰기)
   - **BigQuery 작업 사용자** (로드 잡 실행)
3. 만든 계정 → 키 탭 → **키 추가 → 새 키 만들기 → JSON** → 파일이 다운로드됩니다.

### 3. GitHub Secrets 등록

레포지토리 → Settings → Secrets and variables → Actions → **New repository secret**

| 이름 | 값 |
|---|---|
| `DART_API_KEY` | 재발급받은 DART 키 문자열 |
| `GCP_SA_KEY` | 2번에서 받은 JSON 파일의 **전체 내용을 그대로 붙여넣기** |

시크릿은 퍼블릭 레포에서도 로그에 노출되지 않습니다. 단, 코드나 커밋에는 절대 넣지 마세요.

### 4. BigQuery 샌드박스라면 결제 계정 연결 검토

샌드박스는 **모든 테이블이 60일 후 자동 삭제**됩니다. 분기마다 쌓아 올리는 파이프라인에는
치명적이라, 계속 굴리려면 결제 계정을 연결해야 합니다. 무료 티어(저장 10GB, 월 쿼리 1TB)는
그대로라 이 데이터 크기에서는 실제 청구액이 0원입니다.

### 5. 첫 실행은 수동으로

푸시한 뒤 Actions 탭 → **DART to BigQuery batch** → **Run workflow**.
스케줄을 기다리지 말고 여기서 한 번 돌려 로그를 확인하세요.

## 수집 대상 바꾸기

`load_dart.py` 상단만 고치면 됩니다.

- `TARGETS` — 기업 추가/변경 (`corp_code: 기업명`)
- `START_YEAR` — 몇 년치부터 쌓을지
- `FS_DIVS` — 별도 재무제표까지 원하면 `["CFS", "OFS"]`
- `REPORTS` — 사업보고서만 원하면 `11011`만 남기기

## 동작 방식

**새 분기 감지는 폴링입니다.** 아직 제출되지 않은 분기를 요청하면 DART가 status `013`을
돌려주므로, 그때는 건너뛰고 다음을 확인합니다. 알림을 받는 게 아니라 매주 물어보는 방식이라
별도 트리거가 필요 없습니다. 보고서 제출 기한이 분기말 후 45일(분기·반기),
사업연도말 후 90일(사업보고서)이라 주 1회로 충분합니다.

**적재는 전체 재적재(replace)입니다.** 8주차 Day3 1-3의 멱등 패턴 (1)과 같습니다.
기업 몇 곳 수준에서는 매번 전부 다시 부어도 수만 행이고, BigQuery 로드 잡은 과금 대상이
아니라 비용이 0원입니다. 대상이 수십 곳으로 늘어 API 호출이 부담되면 그때 하이워터마크
append(패턴 2)로 바꾸면 됩니다.

**안전장치**: DART 장애 등으로 수집 결과가 0건이면 적재를 중단합니다. 그대로 replace하면
멀쩡한 테이블이 빈 테이블로 덮이기 때문입니다.

**`loaded_at` 컬럼**: 언제 적재됐는지 남기는 감사 컬럼입니다. 재실행하면 이 값만 갱신되므로
행 수·금액 기준으로는 멱등이지만 컬럼 값까지 완전히 동일하지는 않습니다
(강사노트의 "멱등성 vs 재현성" 항목과 이어지는 지점).

## 로컬에서 시험해보기

```bash
pip install -r pipeline/requirements.txt
DART_API_KEY=발급받은키 DRY_RUN=1 python pipeline/load_dart.py
```

`DRY_RUN=1`이면 수집과 정제까지만 하고 BigQuery 적재는 건너뜁니다.
BigQuery까지 확인하려면 `DRY_RUN`을 빼고 `gcloud auth application-default login`을 먼저 실행하세요.

## 주의: 60일 무커밋 시 스케줄 중지

GitHub Actions는 레포에 60일간 커밋이 없으면 예약 실행을 자동으로 중지합니다
(사전에 메일로 알려줍니다). 강의 자료를 계속 업데이트하는 레포라 실제로 걸릴 일은 드뭅니다.
